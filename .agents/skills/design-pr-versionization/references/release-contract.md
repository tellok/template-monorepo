# 共享发布契约

本文件只定义两平台共用的行为契约。事件、YAML、平台权限、组件调用及 API 在各自平台指引维护。只读当前任务需要的平台文件。

## 版本准备、验证与正式交付分离

```text
功能请求：记录 Changeset → 合并结果检查 → 审阅并合并
默认分支普通提交：轻量检测未消费 Changeset → 创建/更新版本请求
版本准备：隔离消费 → 版本/锁文件/CHANGELOG/来源证据 → 待审请求
版本请求：独立合并结果检查 → 审阅并合并
合法版本合并：先核实发布来源 → 质量门禁 → 构建并验收一次
正式交付：按需传递同一构建 → 镜像/包/Release/合格文档
终结：确认消费者全部停止 → 精确清理本次临时传递制品
```

- 请求维护仅做检测、固定 CLI 的版本准备、范围/来源核对、正文及请求维护。不构建产品，不生成或上传产品制品，不写镜像/包仓库，不创建 Release 或部署；不等待产品质量/构建任务才创建版本请求。
- PR/MR 验证独立执行质量检查、必要构建和本地容器验收，不上传发布传递制品、不写发布仓库。合并前的验证构建不直接充当合并后的正式交付构建。
- 普通默认分支提交只维护版本请求；项目已有常规质量检查可独立运行。正式产品链仅由已核实的合法版本请求合并来源启动，不因创建版本请求提前发布提交镜像。其他预发布渠道另行设计和授权。
- 固定项目安装的 Changesets CLI，依据配置确定固定、关联或独立版本组，不强制全部包同步版本。用户可观察变化按项目约定记录 patch/minor/major；免变更集的范围按项目契约判断。
- 在干净隔离检出中消费 Changesets，提交实际版本、锁文件、CHANGELOG 和来源证据。版本准备不等于包上传，不因生成 Release 自动执行包发布命令。
- 无有效变更不创建空请求；新默认分支提交更新同一受管理请求。分支写入使用租约或等价保护，过期运行不覆盖新结果；未知写入先回读，避免重复创建。

### 未消费 Changeset 检测

检测事件绑定源码树中的存量候选，排除 README、隐藏文件和元数据；以项目固定 CLI 的发现规则为准。不能只看本次 push 的文件变化：已有 Changeset 本次未修改时，仍需维护版本请求。

无候选时跳过准备所需依赖安装、版本生成、分支/请求写入和额外维护调度；有候选后仍由 CLI 核实格式及有效发布项。格式错误明确失败，无有效发布项不创建空请求。已消费文件不再触发维护，仍有新文件则维护后续版本。

此检测只控制版本请求维护，不控制必要的 PR/MR 重检或正式发布来源核实；合法版本合并通常已消费文件，不能因此跳过正式链。

### 版本正文与发布说明

版本请求展示拟发布版本、基础源码、用户变更、影响单元及链接，标明尚未发布，不自动合并。正式说明从发布源码提交的各实际版本 CHANGELOG 精确章节生成，按级别分组、合并跨包重复项并保留范围和来源链接；章节缺失、重复或不可解析时阻断，语言按项目约定。

管理正文有稳定标记，重跑只替换管理块并保留最新读取时的外部人工说明；不使用旧默认分支或未消费 Changeset 拼补正式说明。未知响应须回读，正文刷新不代表获得跨请求的原子写租约。

## 合并结果检查与执行信任

- 所有开放功能及版本请求的来源或实际目标更新，都需重跑全部必需检查；目标不限定为默认分支。验收最新来源合并到最新目标的结果，不只验收来源，也不沿用旧目标成功。
- 优先原生事件和临时合并结果，核对真实来源/目标引用与合并身份。合并引用滞后时等待、重新核实；必要补充只解决已验证缺口，不移动来源或目标引用。
- 实际代码、安装/构建/测试/校验脚本及验证工作流来自同一合并结果。检出代码不会自动替换已经解析的 CI 配置；若平台解析基准不同，明确差异并补充验证配置验收，不能把只检出源码说成已验证全部配置。
- 固定请求编号、来源项目/分支/SHA、目标分支/SHA、合并结果和运行身份，入场及回报前再核对。按请求取消过期排队和运行检查，旧结果不覆盖新结果，不取消其他请求或正式发布。取消必须可终结，不能由无条件回报作业持续占队。
- 目标更新重检与 Changeset 检测独立；没有 Changeset、来源 SHA 未变、非默认目标都不能跳过。合并冲突或身份无法确认应失败，不退回“仅来源检查成功”。
- 可信控制代码只做审批、调度、取消、来源与结果归属核对，不执行未获许可的来源代码。实际验证保持隔离和最小权限，不获得发布秘密、宿主特权或控制器权限。
- 按贡献来源、真实仓库权限及平台政策判断运行信任：有权限协作者及授权自动化可自动运行，外部贡献按原生政策批准。不仅凭作者名、机器人名或分支名认可信任，不默认追加所有者逐提交 Review 许可证。
- 合并审批与执行审批分别设计；目标重跑、显式调度和重试必须维持同等信任边界。无法可靠继承原生许可时等待或采用最小补充门禁，不通过可信调度器绕过批准。

## 正式发布资格、同源与恢复

构建和生成传递制品前核实：原项目默认分支、受管理版本请求已合并、事件源码与实际合并来源对应、Changeset 消费证据、版本/锁文件/目标 CHANGELOG 一致。适配项目实际 merge/squash/rebase 策略，不假设所有平台共享一个合并提交字段。质量及验收全部通过才交付。

普通提交、功能分支、外部请求、手工标签或手工运行不能仅凭版本号获资格。人工补跑核实原身份；独立人工发布渠道需明确定义。默认不创建每提交预发布、build-SHA Release 或临时下载版本。

- 发布清单关联完整源码、实际版本、已验收构建、平台、镜像/包 digest 和文件校验和；文档及公开接口来自同一版本，不从最新分支补旧版文件。
- 容器离线归档从已核实 digest 导出，不再次构建；镜像 digest 与归档校验和分别记录。
- 重跑复用已验证的固定身份，只补缺项；正式资产/包版本有字节冲突则失败，不暗改 Git 发布标签。镜像标签按 registry 的正常规则创建/更新，不额外要求策略确认参数，也不承诺客户端提供跨任务不可变性；固定构建身份应记录 digest，不能只依赖可变标签。
- Latest 和生产文档仅推进合格正式版本，按语义化版本（SemVer）比较，不按字符串或完成顺序；串行关键写入，旧运行不能回退新版本。
- 明确清理后是重跑完整原生产链，还是恢复持久保存的同源内容；不能依赖已删除制品承诺只重跑下游。正式交付完成而文档失败时，恢复同版本部署，不创建新版本。历史修复只处理获授权对象。

## 测试日志与文件生命周期

必需测试在作业内生成结构化报告，核对发现与执行、失败/跳过/空套件以及缺少依赖环境等情况。默认不上传报告、异常转储或浏览器 trace；日志/摘要记录脱敏计数、清单、审计及退出码。缺失结果不能显示通过，质量失败阻断发布；报告上传成功不代表测试成功。日志仍受保留、配额和可见性限制，不承诺永久免费完整审计。

| 文件类别 | 用途和保留 |
| --- | --- |
| 作业本地文件 | 同作业构建、检查、导出和上传，本地使用后按执行器策略回收 |
| 临时传递制品 | 有明确跨作业消费者才上传；全部消费者终结后精确删除，有限过期兜底 |
| 正式交付文件 | 用户下载、安装和校验，放在持久正式存储，独立于 CI 临时清理 |

先画生产者/消费者图，说明每次上传必要性。只传显式允许且消费者需要的文件，不上传整个源码、秘密或运行数据；同作业正式上传无需再留 CI 下载副本。不能为省传输合并不可信验证与特权发布。缓存可重建，不是发布来源证明或绕开配额的正式存储。

### 构建缓存

检查实际构建器及数据生命周期。长期执行器可复用本地缓存；临时执行器须核实显式跨任务导入/导出，不能仅凭 Docker 默认有缓存或配置了目录就宣称已经复用。

- Dockerfile 先复制依赖清单、锁文件及必需安装配置/脚本，再安装依赖，最后复制源码；包含真实安装输入，用忽略文件排除无关上下文，不牺牲冻结锁文件或验收。
- 多阶段中间层按后端能力用 max 模式保存；registry 缓存引用与产品镜像分开，拉最终镜像不等于恢复中间缓存。后端根据执行器、网络、容量、配额及权限选取，不强制特定服务或共享路径。
- 结果应加载本地或以等价方式验收同一镜像，不能为了缓存提前发布产品镜像。缓存按项目、平台和信任范围隔离；不可信请求不能写正式构建共用缓存，也不因缓存获发布权限。
- 构建层与包管理器 cache mount 是两层；导出层不保证 cache mount 持久。首次、锁文件变化及未命中仍需可靠下载。缓存不能放宽依赖校验；项目已禁止原生依赖回退源码编译时，下载失败只按约定重试或失败，不为缓存引入编译回退。
- 实测第二次相同输入、仅源码变化、锁文件变化，记录命中步骤、依赖安装执行情况、总耗时和导入/导出耗时。缓存缺失能构建；损坏或不明缓存不能作为发布证据。

### 临时制品回收

登记项目、完整源码、执行、生成尝试、生产作业、对象/制品身份、消费者和兜底过期。同 SHA 的并发或重跑仍是不同生成，消费和清理使用同一真实生产身份。

成功/失败/取消终态回收前确认全部消费者已停止，覆盖分页；只删除本次精确对象，不按分支、前缀或 SHA 批删，不碰正式资产、日志、镜像或其他项目。删除前回读身份，未知响应再次确认不存在，拒绝/无法确认报错；清理失败单独可见，不掩盖原始失败。

可信终态处理器不检出或执行来源代码，不下载制品脚本，使用最小删除凭据。尾部清理不能保证整体取消、超时、执行器失联时必达；有限过期及受控补偿兜底，保留期覆盖最大消费时间。核实平台保留例外、删除权限和异步计量，删除成功不等于配额立即恢复。历史空间应急删除须有明确对象范围，不自动扩展长期回收权限。

## 验收清单

按实际使用的发布单元和功能选取，分别记录本地、故障替身和真实平台证据：

- 来源更新、非默认目标更新、全部受影响请求重检；无 Changeset 不跳过重检；旧排队/运行取消，冲突不退回仅来源成功。
- 最新来源/目标/合并身份一致，临时合并不移动双分支；合并中的安装/构建/测试脚本和验证配置修改确实生效。
- 协作者与授权自动化按政策自动执行；外部来源未获执行许可不能通过原生、重试或补充入口运行。
- 版本维护无产品构建/上传依赖；无候选、仅 README/元数据、已有候选本次未改路径、错误候选、无有效项、消费后零文件均行为正确；检测早于安装依赖。
- 正式构建前发布资格核实，普通事件不交付；同一正式构建验收后复用于全部消费者，说明取精确版本章节，缺少/跳过必需测试阻断。
- 缓存三种输入变化、未命中与容量策略；制品上传/下载中断、分页、重试隔离、未知删除、成功/失败/取消回收；正式下载清理后仍可用。
- 同源摘要/校验和、远端冲突、新旧版本并发、Latest 防回退、清理后恢复和同版本文档重试。

共享依据：[Changesets CLI](https://changesets.dev/guide/cli)、[Docker 缓存优化](https://docs.docker.com/build/cache/optimize/)、[registry 缓存](https://docs.docker.com/build/cache/backends/registry/)。平台资料分别在对应指引维护；落地时核对当前版本。
